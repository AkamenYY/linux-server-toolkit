# Конфигурация

## Расположение файлов

| Файл | Назначение | В репозитории |
|------|------------|---------------|
| `config/toolkit.conf.example` | Эталонный пример со всеми параметрами и комментариями | да |
| `config/toolkit.conf` | Рабочая конфигурация конкретного сервера | **нет** (`.gitignore`) |
| `config/toolkit.local.conf` | Локальные переопределения разработчика | **нет** (`.gitignore`) |

Почему рабочий файл не хранится в Git: он специфичен для машины и может
содержать внутренние пути и адреса. В репозитории лежит только пример —
это стандартная практика (аналог `.env.example`).

## Порядок загрузки

Скрипты читают конфигурацию так:

1. значения по умолчанию, зашитые в самом скрипте;
2. `config/toolkit.conf`, если файл существует;
3. переменные окружения — имеют наивысший приоритет.

Благодаря третьему пункту любой параметр можно переопределить на один запуск:

```bash
BACKUP_RETENTION_DAYS=30 ./scripts/backup.sh
```

## Параметры

### Общие

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `TOOLKIT_LOG_DIR` | `/var/log/linux-server-toolkit` | Каталог журналов |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARN` или `ERROR` |

### Резервное копирование

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `BACKUP_SOURCES` | `/etc /home /var/www` | Список каталогов через пробел |
| `BACKUP_DEST` | `/var/backups/toolkit` | Каталог назначения |
| `BACKUP_RETENTION_DAYS` | `14` | Срок хранения в днях, минимум `1` |

`BACKUP_RETENTION_DAYS` — самый опасный параметр во всём проекте. Он
управляет удалением файлов, поэтому скрипт обязан проверять, что это целое
число не меньше единицы, и аварийно завершаться при любом другом значении.

### Проверка здоровья

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `DISK_USAGE_THRESHOLD` | `85` | Процент заполнения диска для WARNING |
| `MEMORY_USAGE_THRESHOLD` | `90` | Процент занятой памяти для WARNING |
| `LOAD_AVG_THRESHOLD` | `2.0` | Load average на ядро |
| `CRITICAL_SERVICES` | `sshd cron` | Службы, которые должны работать |

## Безопасность

```bash
sudo chown root:root config/toolkit.conf
sudo chmod 640 config/toolkit.conf
```

Конфигурация подключается через `source`, то есть её содержимое исполняется
оболочкой. Файл с правом записи для всех пользователей — это готовый вектор
повышения привилегий: любой, кто может его изменить, выполнит свой код от
имени root при следующем запуске задачи из cron.

## Проверка конфигурации

```bash
bash -n config/toolkit.conf   # синтаксическая проверка без выполнения
./scripts/sysinfo.sh --show-config
```
